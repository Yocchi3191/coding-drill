# 出題ルール

出題タスクは、このルールに従って、課題を1つ出す。

## 課題の条件

- 1時間で、解き終わる、または終わらなくても形が見えるくらいの規模にする。
- 技術は限定しない。言語、フレームワーク、DBの指定は問題文に書かない。選ぶのは解く人で、選んだ根拠を説明させるためである。
- 仕様は、実装できる程度には書くが、エラーケースは書かない。解く人が自分で洗い出すためである。
- 題材は幅広く自由にする。Webやサービス系なら、DB設計やAPI設計・実装を中心にする。ゲーム、アプリ、組み込み系なら、アルゴリズムやソフトウェア設計を中心にする。
- すでに `problems/` にある課題と、題材が重ならないようにする。直近の課題とは、ジャンル（Webサービス、ゲーム、組み込みなど）も変える。

## 採点側に渡す情報

問題文HTMLの末尾にある、HTMLコメントの採点用ブロックに書く。画面には出さない。形式は `templates/problem.html` のとおりにする。

- **クリティカルなエラー:** 見落とすと、機能が成り立たない、またはデータが壊れるもの。個数に上限はない
- **軽微なエラー:** 見落としても、機能の中心は成り立つもの
- **質問するケース:** 採点時に質問係が聞く状況。実装の工夫した点や、採用しなかった案を引き出せるもの

採点用ブロックの内容は、問題文の本文には書かない。本文に書くと、エラーを洗い出す練習にならない。

## 締切

- 締切は、出題の翌日の日曜の8:00〜9:00（日本時間）。出題は土曜の8:00に実行される
- 問題文HTMLの雛形にある開始時刻と終了時刻の2か所に、日曜の日付を `+09:00` つきで入れる

## 配置

- 問題文は `problems/<日付>_<題材>/index.html` に置く。`<日付>` は日曜の日付（`YYYY-MM-DD`）、`<題材>` は英数字とハイフンの短い名前
- `templates/problem.html` をもとに作る
- 作ったら、`main` にコミットして push する。Cloudflare Pages が自動で公開する
